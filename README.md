- связка Bitrix24 ↔ 1С: заявка → сделка → счёт в 1С → оплата без двойного ввода;

- блок «Из чего складывается стоимость» — лицензии / внедрение / сопровождение;
- в ценах — три готовые связки: CRM + Бухгалтерия, CRM + ЗУП, CRM + УТ/ERP;
- в форме заявки есть поле «Направление»: Bitrix24 / 1С:Франчайзинг / Bitrix24 + 1С.

Ссылки вида «Обсудить 1С» помечены `data-direction="1c"` — направление
подставляется в форму автоматически. Работает и ссылка `?direction=1c`.

## Сборка и запуск

```bash
cd /home/paladin/site
npm install          # один раз: ставит tailwindcss и @tailwindcss/cli
npm run build        # пересобрать assets/css/site.css
npm run watch        # пересобирать CSS при правках index.html
npm run jsonld       # обновить JSON-LD после правки текстов
npm run serve        # локальный сервер на http://localhost:8080
```

Правки в `index.html` после изменения текстов, цен или вопросов FAQ:

1. `npm run build` — если добавили новые классы Tailwind;
2. `npm run jsonld` — чтобы разметка совпадала с содержимым;
3. коммит и push.

Файлы `assets/css/site.css` и JSON-LD коммитятся в репозиторий: сайт открывается
даже без Node.js, а в CI CSS пересобирается ещё раз (шаг не fatal — при отсутствии
npm публикация продолжится на committed-версии).

## Публикация

Сайт публикуется через GitHub Pages. В настройках репозитория
(Settings → Pages → Build and deployment → Source) выбран источник
**«Deploy from a branch» → ветка `gh-pages`, папка `/`**. Поэтому
`.github/workflows/pages.yml` делает ровно одно: собирает статику и
выкладывает её в ветку `gh-pages`.

| Шаг | Что делает |
|-----|------------|
| build | rsync в `_site`, пересборка CSS через `npm run build` (шаг не fatal), проверка наличия `index.html`, `assets/css/site.css`, `sitemap.xml` |
| publish | force-push содержимого `_site` в ветку `gh-pages` — это и есть публикация |

Запуск вручную: GitHub → Actions → «Publish landing» → **Run workflow**.
Каждый push в `main` запускает публикацию автоматически.

> Если захотите перевести сайт на публикацию через Actions
> (Settings → Pages → Source → «GitHub Actions»), нужно добавить в workflow
> джоб с `actions/configure-pages` + `actions/upload-pages-artifact` +
> `actions/deploy-pages`. Сейчас это не требуется: ветка `gh-pages` работает.

### Если публикация не идёт

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Run в статусе `queued` часами | Раннер не стартует: лимиты Actions, отключённые Actions в настройках репозитория или аккаунта | Settings → Actions → General → проверить «Actions permissions» и лимиты; при комбировании снять галку «Require approval» |
| Run завершился `startup_failure` | Workflow не смог запуститься: невалидный YAML, отключённые Actions или проблемы аккаунта | Открыть конкретный Run в UI — там причина; перезапустить после исправления |
| Сайт отдаёт старую версию | Ветка `gh-pages` не обновилась: проверьте статус прогона и дату последнего коммита в ней | Локально повторить публикацию: см. команды ниже |
| Сайт открывает заглушку «Coming Soon» | DNS всё ещё указывает на парковку, а не на GitHub Pages | `dig +short sophia.su` → должны быть `185.199.108–111.153` |

Ручная публикация (копия логики workflow):

```bash
cd /home/paladin/site
rm -rf _site && mkdir -p _site
rsync -a --delete --exclude='.git' --exclude='.github' --exclude='node_modules' \
  --exclude='src' --exclude='scripts' --exclude='package*.json' --exclude='README.md' ./ _site/
cd _site && git init -q && git checkout -q -b gh-pages && git add -A
git -c user.name="deployer" -c user.email="deployer@example.com" commit -q -m "deploy"
git push --force <remote-url> gh-pages
```

Проверка результата:

```bash
curl -s -H "Host: sophia.su" http://185.199.108.153/ | grep -c 'id="1c"'
```

Ожидается `1`. Ноль означает, что на сервере лежит старая версия.

1. **Бренд и контакты** — «София», телефон, e-mail, мессенджеры, юридические ссылки.

3. **Форма** — в `index.html` найдите `const LEAD_ENDPOINT = '';` и укажите свой адрес:
   ```js
   const LEAD_ENDPOINT = '/api/lead';
   ```
   Форма отправляет `FormData` (имя, телефон, компания, направление, комментарий,
   согласие, UTM-метки, адрес страницы). Если адрес пустой — работает демо-режим
   (показывается экран «Заявка отправлена»). При ошибке отправки пользователь видит
   телефон для звонка.
4. **Политика конфиденциальности и оферта** — документы уже созданы (`privacy.html`, `offer.html`), ссылки в форме и футере проставлены. 5. **Отзывы** — блока отзывов нет намеренно: не выдумывайте их. Добавьте реальные отзывы после запуска.

## Технические детали

- Адаптив: mobile-first, контрольные точки `sm / lg`.
- Мобильное меню (закрытие по Esc), аккордеон FAQ (`<details>`), scroll-reveal на
  `IntersectionObserver`, липкий CTA на мобильных (скрывается, когда форма на экране),
  кнопка «Наверх».
- Маска телефона `+7 (XXX) XXX-XX-XX`, подстановка направления из `data-direction`
  и из `?direction=`, honeypot против ботов, UTM-метки в заявке.
- Доступность: `aria-expanded` у меню, `aria-label` у иконок, `role="status"` и
  `role="alert"`, `label` у полей, `prefers-reduced-motion`, `noscript`-фолбэк.
- SEO: canonical, Open Graph и Twitter Card, JSON-LD (`Organization`,
  `ProfessionalService`, `WebSite`, `Service`, `FAQPage` с 10 вопросами),
  `sitemap.xml`, `robots.txt`.
- Цвета, шрифты и тени заданы в `@theme` внутри `src/input.css`.
